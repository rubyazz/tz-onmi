# ONMI: хранение каталога и привязка прайсов поставщиков

Решение тестового задания «прайсы поставщиков и каталог» (B2B-платформа, старт с металлопроката). Фокус этого среза — **схема БД, перечень таблиц и правила маппинга прайс ↔ каталог без ошибок**. Все решения проверены на живом PostgreSQL 16 (см. «Что проверено»).

## Быстрый старт

```bash
docker run -d --name onmi-pg -e POSTGRES_PASSWORD=dev -p 5432:5432 postgres:16-alpine
for f in db/001_schema.sql db/002_seed.sql db/003_views.sql; do
  psql -v ON_ERROR_STOP=1 -h localhost -U postgres -f "$f"
done
# smoke-тесты инвариантов (выводят TEST 1..10 OK):
psql -h localhost -U postgres < db/tests/001_invariants.sql
```

## Что проверено (PostgreSQL 16, docker)

- Схема применяется с нуля без ошибок: 31 таблица, 23 триггера, 6 представлений, сид 7 единиц / 22 атрибута / 27 значений / 25 алиасов / 24 склада Металлсервиса / 22 причины / 7 правил.
- `TEST 1` атрибут вне категории отвергается составным FK; `TEST 2` дубль карточки по identity отвергается, «20.0» канонизируется в «20»; `TEST 3` оцинкованная позиция не встаёт на чёрную карточку (страж привязки); `TEST 4` дубль пары привязки; `TEST 5` вторая активная цена на позицию+склад; `TEST 6` повторная загрузка файла по SHA-256; `TEST 7` привязка к карточке с block-проблемой валидации; `TEST 8` «НН» скрыт политикой; `TEST 9` неполная карточка не получает привязку; `TEST 10` витрина отдаёт ровно одну цену на карточку-склад-поставщика.

## Пять решений, на которых всё держится

1. **Товар = категория + обязательные атрибуты + единица + состояние**, закодировано предвычисленными `identity_hash` (карточки) и `natural_key_hash` (позиции) с уникальными индексами — анти-склейка и анти-дробление держатся СУБД, а не кодом.
2. **Три слоя данных**: raw-строки файлов (append-only) → нормализованные позиции → канонический каталог. Матчинг никогда не сравнивает сырой текст с карточкой.
3. **Страж привязки** (триггер): активная привязка возможна только при полном совпадении identity, совместимых единицах, разрешённой политике состояния и отсутствии block-проблем у карточки.
4. **История вместо перезаписи**: цены и привязки живут интервалами `valid_from/valid_to`, «активная ровно одна» — частичный уникальный индекс; решения журналируются (`audit_log`), у каждой привязки есть метод, автор и трассировка правил.
5. **Справочники вместо хардкода**: новая ниша или новое написание поставщика — INSERT (категория+атрибуты+алиасы), а не релиз. Ручное разрешение спора (новый алиас, новый обязательный атрибут) немедленно делает следующий прайс «умнее».
